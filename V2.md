# Apocrypha v2: conversations are the memory tree

## Architecture

This revision realigns Apocrypha with UniiChat's message-as-leaf design. Each recorded conversation turn is stored verbatim in TRANSCRIPTS.jsonl and represented by one leaf in LOG.txt. Curated notes and turn leaves share one append-only log, in append order, and the same aligned binary summary tree. The existing 320-byte log records, 288-byte tree records, and 280-byte note/summary text limit are unchanged. Full transcript text has no application cap.

A fresh turn leaf is `t<n> <vendor>: <summary>`. The optional `turn.summary` is supplied with the assistant's capture call. Missing or whitespace-only summaries use the whitespace-collapsed user message. The entire leaf text, including its prefix, is shortened at a UTF-8 character boundary with a final ellipsis if it exceeds 280 bytes. The full turn remains uncapped in TRANSCRIPTS.jsonl.

Existing citation zoom is the bridge: recall a settled root range, follow child ranges to a raw leaf, then recall its #n ID. The leaf's tN citation returns the full turn and conversation link. No parallel transcript tree or second citation mechanism exists. Summary prose need not preserve every turn ID because the structural ranges preserve the path to the leaves.

## Capture and idempotency

`note({turn:{vendor,user,assistant,summary?,conv?,turn?,requestId?,omitted?}})`

The single prescriptive tool-text passage is CAPTURE_INSTRUCTION. It records the user message, full intended visible reply, and one-line summary before the reply is emitted unchanged. On first capture the server mints a conversation token; the visible origin-marker footer is appended afterward and is not part of the saved reply. Later captures use the same bare token.

Request IDs deduplicate identical turn writes. Changing a supplied summary with the same request ID is a content conflict. Old request hashes remain compatible when summary is absent. Transcript text, including numbers, is stored verbatim. Origin markers remain excluded; no number screening or content-category exclusion was added.

## Reconciliation and recovery

The existing conservative Linux writer lock was extracted into writer-lock.js and now also serializes log appends, tree saves, forgets, and reconciliation. A turn is fsynced first, then reconciliation appends missing leaves under that same lock. A retry of an already stored request also reconciles. Startup reconciles all missing leaves.

A leaf is identified only by the `tN ` prefix at the beginning of its note text, after the fixed log ID/date. Mentions elsewhere do not count. Reconciliation rechecks under the lock, so repeated or concurrent attempts never add a second leaf. A crash between transcript fsync and log fsync is repaired on restart or retry.

Historic/repaired leaves retain the date they are appended in the log metadata and include their original date in the text: `t5 claude 2026-10-20: …`. With a background model, missing historical summaries are generated before each leaf is appended. Each completed leaf is durable immediately; a later provider failure retries only missing leaves. Without background generation, reconciliation uses the excerpt fallback. Model calls never hold the writer lock.

Read-only preflight:
`node scripts/reconcile-turns.mjs /var/lib/apocrypha --dry-run`
This command creates no files and repairs nothing. Partial records fail closed.

Transcript JSONL corruption is preserved for operator inspection, not truncated. Independent legacy note/recall tools remain usable. Writer-lock recovery still requires proof of a dead same-host/boot/PID-namespace owner; live, foreign, ambiguous, old-boot or recovery-guard locks are not automatically removed.

## Background compaction and in-band option

`APOCRYPHA_COMPACTION_MODE=background` is the default. The service owns one background compactor, shared by all stateless MCP requests. It selects the next task, generates a faithful summary, validates it, and saves through the existing sleep path. Network calls occur outside the writer lock; a changed task discards stale output. Forget leaves the raw log untouched and the background loop rebuilds the invalidated summaries.

Validation rejects empty, multiline, origin-marker, or over-280-byte model outputs without saving. Whitespace is collapsed before the byte check. The internal prompt preserves inference/correction labels and vendor/topic information and treats source text as data. Retries back off exponentially from one second to one minute. Logs include events, ranges, counts, timestamps and errors, not transcript contents or credentials.

`APOCRYPHA_COMPACTION_MODE=in-band` explicitly pauses automatic compaction and restores the existing assistant sleep-task workflow. This is an operator environment setting, not the default. apocrypha_sleep remains available in both modes. Without a configured or healthy compactor, wake falls back to the existing in-band task.

Healthy background wake returns immediately: settled cover blocks appear as summaries; unsettled blocks expand to available children or raw records. It reports pending-block count and paginates below the existing 20 KB response boundary. Once settled, the usual 96-line age-weighted cover applies. A view fingerprint on continuation detects a changed layout during compaction and asks for a fresh first page instead of silently skipping or duplicating lines.

## Subscription first, explicitly configured fallback

The preferred deployment provider is `codex`, using the official Codex CLI with ChatGPT subscription authentication. Codex runs noninteractively, with read-only sandboxing, shell and agent tools disabled, no user config/plugins/hooks, no persisted session, and a fresh working directory per summary. It reads source from stdin and the final reply from an output file. It receives no inherited API keys. The adapter rejects API-key authentication. Subscription quotas still apply.

Proposed environment settings (values live only in /etc/apocrypha.env):
- APOCRYPHA_COMPACTION_MODE=background
- APOCRYPHA_COMPACTOR_PROVIDER=codex
- APOCRYPHA_COMPACTOR_CODEX_HOME=/var/lib/apocrypha/codex
- APOCRYPHA_COMPACTOR_CODEX_BINARY=/usr/bin/codex
- APOCRYPHA_COMPACTOR_MODEL is optional; omitted uses the CLI default.
- Optional APOCRYPHA_COMPACTOR_FALLBACK_PROVIDER=groq
- Optional APOCRYPHA_COMPACTOR_FALLBACK_MODEL=openai/gpt-oss-120b
- Optional APOCRYPHA_COMPACTOR_FALLBACK_API_KEY is the explicitly approved free-tier Groq key.

The fallback is only enabled by explicit configuration. No paid key rotation or automatic switch to another account occurs. Subscription credentials remain in the dedicated Codex auth directory and are refreshed by the official CLI. Credential provisioning/copying requires Jensen's approval. Existing provider adapters also support anthropic, openai, and groq with explicit model/key settings; they are not automatically selected.

## Wake mirror

At Jensen's explicit direction, the Google Doc is exactly the default wake rendering, including turn leaves, summaries, pending count, headings and page footers. All wake pages are concatenated in order with a blank line between pages. There is no leaf filter, curated-only copy, or separate full-log presentation. Full transcripts appear only when zoomed and therefore are not inserted into the wake mirror.

MCP wake and the Doc share wake-view.js. The mirror refreshes on startup, notes/turns, explicit sleep/forget, repaired leaves, compactor progress and failure state. External Google failures remain best-effort and cannot roll back memory; failed refreshes are logged. The existing document ID, OAuth grants and mirror destination remain unchanged.

## Health and operations

/healthz includes memories, reconciliationError and compactor state: mode, configured, running, pendingLeaves, pendingBlocks, lastSuccess, lastError, consecutiveFailures, nextRetryAt, backend and lastFallback. Backfill and block compaction are separately visible. API and CLI failures retry; they do not invent summaries.

Source delivery remains Praxis sync → managed workspace → npm test → review → commit → push → deployment_fast_forward. Source is never edited in /srv/apocrypha. Runtime data, configuration and login state are separate from deployment and never committed.

## Existing v2 resolution and reads

Conversation tokens group turns; optional explicit turn numbers increase but do not prove no turns were missed. Server timestamps use Pacific local ISO time including DST offset. Explicit link resolution requires a canonical matching-vendor ChatGPT/Claude chat URL and a retrieved candidate containing the exact origin marker. Evidence snippets are hashed, not saved. Ambiguous origins link neither chat; corrections require the explicit correction flag. Ten failed attempts spanning seven days mark a conversation unresolvable. Automatic unresolved-token listing remains disabled in production.

Recall retains range/id/regex reads, 20 KB UTF-8-safe pages, read fingerprints, and one-second regex execution deadlines. Transcript operations still read and validate full JSONL histories; a large history eventually warrants an index. The tree reduces wake presentation size, not transcript storage. No deployment proves a client's cached schema refreshed.
