## Zoom and paging
Recall accepts exactly one of pattern, inclusive aligned range (16-31), or id (#42/t412). Internal half-open ranges are unchanged. Blocks must already be settled. Above size 16 return two child summaries; smaller blocks return precisely the raw merge inputs. Note IDs follow bounded tN citations into transcript leaves. Missing or invalid child records fail with forget/rebuild instructions rather than silently skipping.

part and snapshot are optional read-only paging fields. Returned continuation pins a SHA-256 read fingerprint; a changed transcript link/content requires restarting the read. Pages, including headers and continuation, are at most 20,000 UTF-8 bytes, without splitting characters. Regex searches preserve JavaScript syntax but run in a worker with a one-second deadline and return newest bounded matches; long transcript hits are explicit excerpts that can be zoomed. Regex construction and timeouts do not change source stores.

## Transcript writes
note({turn:{vendor,user,assistant,conv?,turn?,requestId?,omitted?}})
- vendor is explicitly claude or chatgpt.
- Omit conv only on the first captured turn. The server mints a collision-checked cryptographic apx token and returns the bare token and tN ID.
- requestId is a stable per-operation key (8–128 safe characters). Retry identical arguments with the same key; changed content rejects. Without a key, uncertain writes must be inspected before retrying.
- Optional turn is the actual known vendor turn number and must increase. Omitted turn numbers are assigned among captured turns only, so they DO NOT prove which vendor turns were missed.
- No application cap on turn size. The HTTP body limit is 16 MB (server.js; Express's 100 KB default is overridden) so that client tool-argument and output limits are the binding constraints. nginx for mcp.jensenabler.com must also allow it (client_max_body_size), which is host config outside this repo. omitted:length remains available if a client truncates.
- omitted contains only id, account, suicide, self-harm, disordered-eating, attachment, or length. The assistant is responsible for omitting excluded semantic categories; numeric pattern checks cannot detect everything. Numeric pattern rejection is scoped to transcript writes, as specified; curated note and compression validation retain their legacy length/normalization behavior. Their standing exclusions still apply.
- Timestamp is server Pacific local ISO time including UTC offset; DST is tested.
- The tool response contains only IDs/provenance, not a second copy of the turn text.

Origin-marker timing differs from the circular draft: finish the reply body, capture that body, then emit the returned origin marker as a separate final visible line. The marker itself is deliberately absent from the stored transcript. Never claim that copy includes a later marker/footer. If a client cannot make a tool call after body text, it must not claim exact post-reply capture; leave capture unactivated until its workflow is tested. Markers are rejected from transcript writes and by a separate marker-only guard on curated notes/summaries; use bare tokens in notes, transcripts and handoffs.

## Vendor identification
OAuth verification supplies clientId but no trusted vendor mapping. Dynamic-registration metadata is client-supplied, and static bearer requests have no clientId. No private OAuth records were inspected. v2 therefore accepts explicit vendor on turns and optionally wake, and requires it for resolve; resolve compares it to the stored conversation. This is caller context, NOT a new authentication boundary. Same-owner authorization remains unchanged. Do not infer vendors from names or redirects.

## Resolution
note({resolve:{token,vendor,url?,candidates?:[{url,snippet}],correction?,outcome?:missing,requestId?}})
A resolved URL must be an exact canonical HTTPS chatgpt.com/c/UUID or claude.ai/chat/UUID for the stored vendor, with no credentials, extra path, query or fragment. Each candidate snippet must contain the exact origin marker for that token. Bare-token hits and missing evidence reject. The server validates supplied evidence, not the vendor search itself; the assistant must actually retrieve the candidates and must not fabricate snippets.

Two different marked URLs resolve neither: omit url to append an ambiguous attempt. Ambiguity remains flagged across later missing attempts. Known ambiguity or an existing link requires explicit reviewed correction before resolving. Raw snippets and marker strings are never persisted; provenance uses hashes. A failed read is recorded with outcome:missing and no candidates. Stable requestIds deduplicate attempts.

Unresolved suggestions are disabled by default because native-search indexing coverage remains unverified. Explicit evidence-validated resolution remains available. The server factory's lazyResolution option is the gate; production server does not enable it. Activating the gate requires a later reviewed change after successful own-vendor probes (or an export-importer design), not a claim that current misses prove indexing lag. When enabled, wake takes explicit vendor, preserves it across pagination, lists at most five oldest unresolved conversations, and flags ambiguity. Do not automatically retry ambiguous tokens; ask Jensen to review.

Ten failed attempts across at least seven days mark unresolvable. Failed count and first failure timestamp persist; repeated identical keyed attempts do not count again. Coverage claims must distinguish unrecorded turns, failed search and unavailable vendor history.

## Durability and recovery
TRANSCRIPTS.jsonl and CONVERSATIONS.jsonl are append-only, fsynced and not Drive-mirrored. A conservative exclusive writer lock serializes writers across instances. A crash can leave an orphan created-conversation event; the original first-write requestId safely reuses it. A partial record or malformed history fails closed and is preserved for operator inspection, never automatically truncated. Linux writer locks now record local machine/host/boot/PID namespace/PID/start identity. A proven dead same-host, same-boot, same-namespace owner can be recovered; a live or unverifiable owner, foreign host, previous boot, or legacy lock remains operator-only. All acquire/release/recovery transitions use the same exclusive guard and immediately revalidate lock inode, metadata and owner death before removal, including PID-reuse checks. A crash while holding the brief recovery guard requires operator inspection; the guard is never recursively broken automatically. Guard contention waits synchronously for up to about one second, temporarily blocking this Node process; sustained contention needs operational review. Independent log-only tools remain usable if transcript storage is corrupt.

Existing backups were not inspected or modified. Confirm that the established /var/lib/apocrypha backup actually includes these new files before enabling capture. Forget still changes only summary files, never transcripts.

## Scale and continuation limitations
Transcript operations currently reread and validate the complete JSONL histories. This favors simple fail-closed recovery over indexing complexity, but memory use and latency grow with captured history. There is no persisted search index or transcript compression tree in this version; test representative volumes before broad long-term capture. Regex searches have a bounded execution deadline, but loading/validating history is synchronous and is not covered by that regex deadline.

Wake continuation is now generated structurally by the store with the requested vendor, rather than rewriting returned text with a regex. Embedded tool-like note text is never parsed. Transcript paging pins its content fingerprint, so an intervening link change requires restarting the read.
